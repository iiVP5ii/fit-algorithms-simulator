Chapter 5: Memory Management (Operating System Concepts)
Direct academic study reference based on the textbook Operating System Concepts (Silberschatz, Galvin, Gagne) for university Operating Systems courses.
1. Contiguous Memory Allocation (Slide 7)
In contiguous memory allocation, each process is contained in a single contiguous section of physical memory:
  • Multiple-partition allocation: Memory is divided into several partitions. Each partition contains exactly one process.
  • Hole: A block of available free memory. Holes of various sizes are scattered throughout memory.
  • When a process arrives, it is allocated memory from a hole large enough to accommodate it.
  • When a process terminates, it frees its partition, and adjacent free holes are merged together (coalescing).
2. Dynamic Storage-Allocation Strategies (Slide 8)
How to satisfy a request of size \( n \) from a list of free holes:
First-Fit:

Allocate the first hole that is big enough. Searching can stop as soon as a hole that fits is found. Generally the fastest algorithm.

Best-Fit:

Allocate the smallest hole that is big enough. Must search the entire list unless ordered by size. Produces the smallest leftover hole.

Worst-Fit:

Allocate the largest hole available. Must search the entire list. Produces the largest leftover hole, which may be more useful than tiny leftover fragments.

3. Slide 9 Exercises & Solved Solutions
Exercise 1: Core Benchmark
Partitions: [100, 500, 200, 300, 600] KB | Processes: [212, 417, 112, 426] KB
• First Fit: Allocates P1 to 500, P2 to 600, P3 to 200. P4 (426 KB) fails because remaining free holes are only 100 KB and 300 KB. Total internal fragmentation = 559 KB.
• Best Fit: Allocates P1 to 300, P2 to 500, P3 to 200, P4 to 600. All 4 processes succeed (4/4)! Total internal fragmentation = only 433 KB.
• Worst Fit: Allocates P1 to 600, P2 to 500, P3 to 300. P4 (426 KB) fails. Total internal fragmentation = 659 KB.
Exercise 2: Exact Fits & Unusable Holes
Partitions: [50, 100, 200, 350] KB | Processes: [45, 50, 80, 120, 200] KB
• Exact Fits: Process P2 (50 KB) exactly matches partition 50 KB, and process P5 (200 KB) exactly matches partition 200 KB without any internal fragmentation.
• Unusable Holes: When P1 (45 KB) is assigned to the 50 KB partition, only 5 KB remains—a tiny leftover hole that cannot fit any pending process.
Exercise 3: Process Arrival Order Effect
Partitions: [300, 100, 350, 600, 200] KB | Processes: [115, 500, 210, 90, 430] KB
• Original Arrival Order: Small process P1 (115 KB) grabs the initial 300 KB partition, preventing larger subsequent processes from finding suitable blocks.
• Sorted Descending Order: Sorting processes from largest to smallest allows large requests to claim large partitions first, dramatically improving First Fit success rate!
4. Memory Fragmentation (Slide 10)
  • External Fragmentation: Total memory space exists to satisfy a request, but it is not contiguous; storage is fragmented into a large number of small holes scattered across memory.
  • Internal Fragmentation: Memory allocated to a process is slightly larger than requested memory. The unused space within the allocated partition is internal to that partition and cannot be used by other processes.
  • 50-Percent Rule: Analysis shows that given \( N \) allocated blocks, another \( 0.5 N \) blocks will be lost to external fragmentation. That is, 1/3 of memory may be unusable!
